# Token消耗高级优化（QQ机器人套件）· astrbot_plugin_qqmind

> 原作者：**本少** (DanDingBenShao) · B站教程/演示：[本少-淡定版](https://space.bilibili.com/411821291)
> 现维护：**本人的鱼** (E4-Kahn) · 本仓库：[E4-Kahn/astrbot_plugin_qqmind](https://github.com/E4-Kahn/astrbot_plugin_qqmind)

为 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 装上一套可配置的群聊记忆管线：**浅层判读门省 token，深层记忆可寻回**。

## 核心思路

群里的消息 99% 不需要 AI 回。qqmind 在主模型之前加一道**浅层判读门**：只喂最近几条群消息，判断"这条是不是在对 AI 说话"——判否只拦主模型（每条判读约几百 token，相比一次完整回复动辄数千 token，拦截即回本），判是才进主模型。判读判"需要动脑"的创作/推理类请求会自动切到思考模型，闲聊走轻快模型。

判否的消息**只拦 LLM、不终结事件链**：其他插件、`/` 命令、AstrBot 内置指令完全不受影响。

## 四档套餐

| 档位 | 读取方式 | 适用场景 | 200 条群聊实测消耗 |
|---|---|---|---|
| 轻量 light | 只回 @ | 安静群 / 省到底 | 最低 |
| 全量 full | 每条判读，判是才回 | 中等活跃群 | ≈77k tok（-26%） |
| 分层 layered | 浅层原文 + 深层群日记 | 重度聊天群 | ≈38k tok（-63%） |
| 高级 advanced | 四轴自选（攒批判读/精确记忆/随机读） | 想精细控成本 | ≈12k tok（-88%） |

对照基线（全量读、无判读门）≈104k tok/200 条。判读次数是第一成本因子。

## 记忆能力

- **群聊**：唤醒、读取、记忆、回复四条轴独立可调；支持按 QQ 号每人一条精确记忆线（默认 4000 token，溢出压成群日记；v0.4.0 起精确记忆线并入公共时间线，`precise_memory` 开关保留但等价于平铺窗口）
- **私聊**（v0.3.2）：窗口按 token 预算管理（默认 10000），溢出自动压成日记；窗口随该用户日记库持久化，**插件重载/重启不再失忆**；「还记得吗」类提问自动预检索日记；超长消息截断保存（不再整条丢）。「我们昨天聊了什么」也能翻出来（`/日记 最近`、`/日记 关键词`、`/日记 昨天`）
- **群日记入口**：`/群日记 最近|关键词|昨天`，`/群日记 #编号` 看那篇的原话
- **三层日记**：标题+时间（常驻）→ 概要（检索带出）→ 原话全文（`▷` 标记，按需展开）；AI 回忆时概要够答就不展开，省 token
- **日记检索**：标题+时间+标签+摘要，纯 BM25+中文二字组建索引，零 embedding、零额外依赖
- **人设三层**：浅层状态（当前情绪）+ 深层性格（常驻）+ 背景故事篇章库（标题常驻、正文关键词召回）
- **统一记忆**（v0.4.0）：私聊与群聊**共用一条时间线、一个日记库**（`memory.db`）。每条消息带来源标记（`src/gid/uid/nick`），写日记时一起压，读的时候按场景切片——私聊能看到「群里最近在聊」（`private_group_glance_msgs`，默认 6 条，填 0 关闭），群里也能接上私聊的话头。隐私边界：含私聊内容的篇目 `gid=0`，群聊侧只给概要、不给原话（`/群日记 #编号` 也只回概要）；群聊原文进群聊 prompt 的路径只有 `context(scope="group")`，它只取 `src=="group"` 的消息。首次启动自动把旧的 `<uid>.db` / `group_public.db` 并进新库（原文件改名 `.migrated` 备份，幂等可重入）
- **压缩不再堵死**（v0.4.0）：旧版「失败绝不丢原文」= 原文留在窗口里等重试，模型一抽风窗口就无限涨、token 越烧越多。现在把「移出窗口」和「生成摘要」拆开：① 先本地削窗口并落一条**摘录条目**（零成本，原文前 3000 字留在 `content`）；② 再让模型把它升级成正式日记；③ 连续失败 3 次熔断 30 分钟，期间只走本地摘录；④ 每轮顺带补升级一条历史摘录条目。窗口 token 单调下降，**与模型可用性解耦**。同时补了输出解析的降级链（JSON → 截断括号修补 → 字段正则 → 散文兜底）和 `text_chat` 路径丢 `max_tokens` 的老 bug
- **历史数据一键导入**（v0.2.6）：从 DSH/桥接方案迁移，聊天记录批量压成三层日记 + 自动提炼用户画像（进 system prompt）；控制台操作、后台执行、进度可查
- **图片识别**（v0.2.6）：表情包/截图一句话看懂进记忆，GIF 自动抽帧；每日识别预算可控（`vision_budget`）
- **主动私信**（v0.2.6）：休息时段对白名单好友主动找话聊（带记忆接上次话头）；每人每天限 1 条、连续不回应冷却 7 天（`proactive_friends` 空=关闭）
- **分群账本**（v0.2.7）：`/账单` 群里=本群数据+全网总量，私聊=全网；token 与读/回/拦全部按群分账落盘
- **好感度系统**（v0.2.8，`affinity_enabled` 开）：按 QQ 号跨群记一份好感度（互动加分、每日上限防刷），可给每人写备注（作息/称呼/雷点，自动进对话提示词）；主动聊天改为好感度达阈值 + 对方作息内才触发
- **公共群记忆**（v0.3.1）：所有群的候选池与日记库合一（entries 带 gid 记住出处），A 群聊过的梗 B 群接得住；攒够 1000 条压一次，每天凌晨 04:30 残余兜底；**v0.4.0 起连私聊也并进同一个库**（隔离改为「按来源切片」：群聊侧读不到私聊原话，只拿概要）。v0.3.1 修复：合法空结果不再误判失败、单批最多 1000 条防撑爆上下文、入库异常整批回滚、满池丢弃告警、凌晨补扫记账
- **省 token**（v0.3.3）：判读/压缩自动走当前 DeepSeek provider 的非思考副本（V4 默认思考，判读每次白烧几十个 reasoning token）；回复仍由判读结果决定是否思考，不受影响
- **兼容性修复**（v0.3.4）：非数字平台 ID（匿名/频道/第三方适配器的十六进制 ID）不再让 `on_message` 抛 `invalid literal for int()`；这类事件静默跳过，QQ 正常群聊/私聊不受影响
- **审查修复**（v0.3.5）：主动私信 NameError 修复（护栏真正生效：24h 未回应计数→冷却 7 天）、攒批/随机读判读补群名片锚点、历史导入 token 记账、池压缩账单改用真实 usage（去掉恒定虚增 4000）、非空文本 token 估算至少记 1、群缓冲单条超长截断、控制台 XSS 防御加固；下架两个无效配置项（`history_rounds`/`history_dir`）
- **判读瘦身**（v0.3.5）：判读不再带 7 条群聊语境（账单实测语境占判读输入 ~40% 且群越活跃缓存越难命中；98.6% 的判读结论是「否」），只判待判消息本身+群名片锚点，单次判读成本降约六成；回复路径语境不受影响

## v0.4.0 改了什么（相对上游 v0.3.9）

这一版**只动记忆**：判读门、四档套餐、人设、护栏、主动私信、账单逻辑都保持原样，行为不变。

### 1. 私聊与群聊合并成一条记忆线

上游的私聊窗口（`diaries_dir/<uid>.db` 的 window）、群聊窗口（`group_memory_dir/<gid>.json` 的 flat/precise）和群日记（`group_diaries_dir/group_public.db`）是三套互不相通的存储。现在统一成 `diaries_dir/memory.db`，窗口、日记、画像、好感度全住在一个文件里：

- 每条消息带来源标记 `src`（`private`/`group`）与 `gid`/`uid`/`nick`，写日记时**一起压**，不再为私聊和群聊各调一次模型
- 读的时候按场景切片：`context(scope="private")` 只取私聊，`context(scope="group")` 只取本群
- 私聊里能看到「群里最近在聊」（新增 `private_group_glance_msgs`，默认 6 条，填 0 关闭）；群里也能接上一个话题的尾巴
- 隐私边界：含私聊内容的篇目 `gid=0`，群聊侧**只给概要、不给原话**，`/群日记 #编号` 同样只回概要

### 2. 压缩不再把窗口堵死

上游「失败绝不丢原文」的实现方式是原文留在窗口里等重试。模型一抽风（返回散文、截断 JSON、API 抖动），窗口就只涨不消，token 越烧越多。现在把「移出窗口」和「生成摘要」拆成两步：

- `evict_oldest()` 先纯本地把最老一段移出窗口，同时落一条**摘录条目**——零成本，summary 取原文前 200 字，`content` 留前 3000 字，所以原文其实没丢
- `summarize()` 再让模型把它升级成正式日记；模型没给原文时沿用摘录里的原文
- 连续失败 3 次熔断 30 分钟，期间只走本地摘录，**窗口照样缩小**
- 每轮顺带补升级 1~2 条历史摘录条目，欠的账慢慢还
- 结果：窗口 token 单调下降，与模型可用性完全解耦

### 3. 输出解析加了降级链

`json.loads → 剥代码围栏 → 截断括号修补 → 逐字段正则 → 散文兜底`。顺带修掉 `text_chat` 分支**没传 `max_tokens`** 的老 bug（参数被静默忽略，模型按默认值输出，长日记容易被腰斩）。

### 4. 顺带修的串号问题

合并后所有会话共用一个库，原来写死单键的元数据会互相覆盖：

- 好感度 `affection` → `affinity:<uid>`
- 用户画像 `profile` → `profile:<uid>`
- 私聊注入链路里 `p.uid` 恒为 0 导致「读到别人的好感度」，一并修了

### 5. 数据迁移

首次启动自动合并，幂等可重入：`<uid>.db`、`group_public.db`、`<gid>.db` 并进 `memory.db`，窗口消息补 `src`/`uid`，画像与好感度转成新键，原文件改名 `.migrated` 留作备份。

> **升级前建议手动备份一份 `data/plugin_data/astrbot_plugin_qqmind/`。** 迁移失败不影响启动，只在日志里留 warning。

### 行为变化

- `precise_memory` 开关保留，但等价于平铺窗口（精确记忆线并入公共时间线）
- `group_memory_dir` 里的 `flat`/`precise` 不再写入，该目录只留给候选池合批使用

## 护栏

每日 token 预算熔断（烧完自动降级只@）· 每群回复频率上限（兼 QQ 风控保护）· @全体忽略 · bot 互怼拦截 · 判读连续失败自动降级轻量 · 主动私信多重护栏（白名单/每日上限/冷却/时段限制）

## 安装

在 AstrBot WebUI 的插件市场搜索 `qqmind`，或直接从仓库安装：

```
https://github.com/E4-Kahn/astrbot_plugin_qqmind
```

零第三方依赖（纯 Python 标准库 + astrbot.api），装上即可用。

## 快速上手

1. 装好后把机器人拉进群，默认轻量档：只回 @ 消息
2. 在 WebUI 插件配置里改 `group_preset` 为 `full`（逐条判读）或 `layered`（分层记忆）
3. 有创作/推理需求（写诗、解题）建议配置 `judge_model`（如 deepseek-chat，判读快且省）与 `think_model`（如 deepseek-reasoner，判读判「要动脑」的当轮自动切换）
4. 控制台页面（插件详情页）可看今日账本、浏览日记、管人设

## 配置要点

常用键都有中文说明，几个关键的：

- `group_preset`：套餐档位（light/full/layered/advanced）
- `judge_scope`：监控期外是否也判读（烧判读调用，慎开）
- `daily_token_budget`：每日预算，0 不限
- `reply_rate_per_min`：每群每分钟回复上限（默认 6，兼风控保护）
- `allowed_groups`：群白名单，空=不限

## 数据存放（v0.3.6）

所有数据（账本/日记/群记忆/池/角色包）统一存放在 AstrBot 官方插件数据目录：

```
data/plugin_data/astrbot_plugin_qqmind/
```

从旧版本升级**无需任何操作**：首次启动自动把 `data/` 根下的老数据整体搬入新目录（支持用户自定义目录名；显式配置了绝对路径的尊重原样）。目录键现在相对本插件数据目录解析。

## 上下文注入方式（v0.3.7）

遵循官方《调用 AI / 接收消息事件》文档规范：

- **动态内容**（人设状态、日记预检索、好感度备注）走 `req.extra_user_content_parts`
  （`TextPart.mark_as_temp()` 只在本轮生效、不落会话历史），不再写进
  `system_prompt`——保护服务端提示词缓存（官方文档：逐轮变化的 system_prompt
  会破坏缓存，成本约增加 7-20 倍）。
- **群聊语境**：浅层 system 段稳定（前缀不变），逐字语境照常走 contexts 消息数组；
  群记忆/人设**不注入白名单外的群**。
- **私聊**：v0.3.7 起不再用插件窗口整体替换官方会话历史——官方历史照常携带，
  插件窗口只承担「超预算压缩成日记」的记忆管理，双份 token 存储随之消除。

## 已知边界

- 全量档逐条判读在极活跃群可能判读开销超过回复开销（bench 数据见上表），重度群建议 layered/advanced
- 极端长道具/长文场景与生成端无关，本插件只管记忆与判读，不干预生成
